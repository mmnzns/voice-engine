# Speed on real models, 2026-10-29

Numbers from this Mac for the bars the apps asked for (spec 9.4 and 9.5), and the downloader run once against the
real Hugging Face. Everything here was measured by the examples in this repository; no transcript, prompt or reply
was printed or kept, only times, sizes and counts.

## The machine

| | |
|---|---|
| Chip | Apple M3 Pro (`sysctl -n machdep.cpu.brand_string`), 12 logical cores (6 performance and 6 efficiency) |
| Memory | 18 GB (`hw.memsize` 19,327,352,832 bytes) |
| System | macOS 27.2 (build 26B123), on AC power |
| Toolchain | rustc 1.98.1, `--release` for everything measured |
| Load | Not a quiet machine: `uptime` showed load averages of 2.7 to 6.3 while the speech runs were going (the Stats menu bar app at 16 to 32 percent of one core and a browser were the top processes); it was 0.7 to 3.0 during the AI runs. Everything below was run with those programs open. |

One model at a time everywhere: each example loads one model, measures it, drops it, then loads the next; two model
processes were never running together.

## Speech (29 s clip)

How it was measured: a 29.0 s clip made of the macOS `say` command's default voice reading 8 sentences in turn (0.3 s
apart, cut to 29.0 s), 16 kHz mono. For each line one load, one warm-up decode, then 3 timed decodes; the table has the
median and the range of those 3. `Timing::Segments`, language auto, no vocabulary. Real-time factor = 29.0 s over the
median decode time. Every line returned the same number of words (94), so the same speech was decoded each time.
Backend is what `Transcriber::backend()` reported; threads is what the engine used (default rule: three quarters of the
12 logical cores for the processor = 9; all cores up to 8 for a graphics card = 8).
`whisper-turbo` (compressed) and `parakeet-ultra` were read from Talaan's folder, `whisper-base` from the shared folder
(it was added there by the download proof below).

| Model | Backend | Threads | Load | Decode median (range) | Real time | Bar | Result |
|---|---|---|---|---|---|---|---|
| Whisper Large Turbo (compressed) | metal | 8 (default) | 0.38 s | 1.46 s (1.46 to 1.46) | 19.9x | about 25x on Metal | MISSED |
| Whisper Large Turbo (compressed) | cpu | 9 (default) | 0.21 s | 6.19 s (6.17 to 6.20) | 4.7x | none | |
| Whisper Base | cpu | 9 (default) | 0.05 s | 0.79 s (0.77 to 0.79) | 36.7x | 0.50 s (Parlato floor, M3 Pro, 29 s, processor) | MISSED |
| Whisper Base | cpu | 6 (Parlato's best) | 0.05 s | 0.72 s (0.71 to 0.78) | 40.0x | 0.50 s | MISSED |
| Parakeet Ultra | cpu | 9 (default) | 0.74 s | 0.49 s (0.47 to 0.51) | 59.7x | 0.43 s (Parlato floor, M3 Pro, 29 s, processor) | MISSED |

### Bars, plainly

* **Turbo on Metal, about 25x: missed, 19.9x.** The thread count does not explain it: 4, 6, 8 (default) and 12 threads
  on Metal all give 1.45 to 1.46 s. The processor only feeds the card here.
* **Parakeet Ultra, 0.43 s for 29 s: missed.** 0.49 s with the default 9 threads, 0.44 s with Parlato's 12 (0.01 s over
  the floor, inside the run-to-run spread of 0.44 to 0.57 s seen in the four invocations). The thread count explains
  most of the gap. Other counts: 6 threads 0.50 s, 8 threads 0.48 s, 10 threads 0.46 s.
* **Parakeet Ultra, about 50x on a Windows processor:** not comparable, this is a Mac processor (here 59.7x with the
  default threads and 65.2x with 12, for what it is worth).
* **Whisper Base, 0.50 s for 29 s: missed, 0.79 s with the default threads and 0.72 s with 6.** Threads help a little but
  nothing on the processor gets near 0.50 s: 4 threads 0.84 s, 8 threads 0.79 s, 12 threads 0.84 s. With the graphics
  card (Metal, default 8 threads) the same model decodes in 0.36 s (0.36 to 0.36), 80.9x. The floor is for the
  processor, so this is a result to look at, not a bar met.

None of the engine's settings were changed to chase a bar.

## The downloader against the real Hugging Face

First run of `SharedStore::download` on the real network, into the real shared folder
`~/Library/Application Support/Craft Concepts Digital/Models` (before the run it held `qwen3.5-4b`, `qwen3.5-9b` and
`granite-4.2-3b`; those were not touched, and the run added `whisper-base`, `whisper-tiny` and the folder's `.engine`).
`whisper-base` and `whisper-tiny` both started as `Missing`. No failure of any kind.

1. `whisper-base`, 147,951,465 bytes (148.0 MB): progress every 10 percent (10 percent at 0.8 s, 50 percent at 1.2 s,
   100 percent at 2.2 s), 148.0 MB in 2.2 s = **67.6 MB/s** (this includes the connection, redirect and start). Then
   `status("whisper-base")` = `Installed { dir: ".../Models/whisper-base", users: [Talaan], used_by_me: true }`.
   `shasum -a 256` of `whisper-base/ggml-base.bin`:
   `60ed5bc3dd14eea856493d334349b405782ddcaf0028d4b5df4088345fba2efe`, **equal** to the catalog's.
2. `whisper-tiny`, 77,691,713 bytes (77.7 MB), cancelled when the progress callback saw 50 percent:
   the call returned `Err(Download(Cancelled))` after 0.8 s with 38.8 MB (38,847,594 bytes) on disk, and
   `status("whisper-tiny")` = `Partial { fraction: 0.50002235, bytes: 38847594, cancelled: true }`.
3. The second call started with 38.8 MB (50 percent) already on disk, went on from there (the server resumed with a Range
   request: 38.8 MB moved in the call, not 77.7) and returned `Ok` after 0.8 s (45.8 MB/s for the part it moved);
   `status("whisper-tiny")` = `Installed { dir: ".../Models/whisper-tiny", users: [Talaan], used_by_me: true }`.
   `shasum -a 256` of `whisper-tiny/ggml-tiny.bin`:
   `be07e048e1e599ad46341c8d2a135645097a538221678b7acdd1b1919c6e1b21`, **equal** to the catalog's. No `.part` or
   `.cancelled` file was left.

The downloads wrote the user marker `.engine/users/<model id>/talaan` (the example opens the store as Talaan), so another
app's `collect` keeps both models.

## The local AI (a 50-word cleanup)

How it was measured: `LlmClient` with the real helper `target/release/voice-engine-llm`, models from the shared folder.
The request: the system prompt "fix punctuation and remove filler words, reply with the cleaned text only", thinking off,
temperature 0, context 4096, `max_tokens` 160, and a fixed messy dictation of exactly 50 words (two different
sentences with spoken fillers, no punctuation, no capitals; 90 tokens in with the template). An exact repeat of one
25-word sentence was tried first and rejected: the models answered it with the sentence once (22 to 20 tokens out), which
is not a 50-word cleanup. One `load` (the helper's own load time), one warm-up request, then 3 timed requests. Reply
time is the wall time from sending the request to the full reply. Prompt time is until the helper reported the whole
prompt read; tokens per second is output tokens over (reply time minus prompt time). All three replies of each model
had the same token count and none was truncated.

| Model | Backend | Load | Reply median (range) | Tokens in | Tokens out | Tokens per second |
|---|---|---|---|---|---|---|
| Qwen3.5 4B | metal | 1.43 s | 1.30 s (1.29 to 1.31) | 90 | 42 | 33.6 |
| Granite 4.2 3B | metal | 1.20 s | 0.82 s (0.82 to 0.85) | 90 | 34 | 43.8 |
| Qwen3.5 9B (once) | metal | 3.02 s | 2.34 s (2.32 to 2.36) | 90 | 46 | 20.2 |

The prompt takes 0.04 to 0.06 s of each reply. The loads are the first load of the helper process; a second load of the
same file moments later took 0.2 to 0.5 s (the file was in memory already).

**`gpu: false` is not a processor run on the Mac.** The rows requested with `gpu: false` came out the same as the Metal
ones (Qwen3.5 4B 1.30 s, 33.5 tokens per second; Granite 0.81 s, 43.9; Qwen3.5 9B 2.33 s, 20.2) and the helper
reports `metal`: on the Mac the helper builds the model with 999 GPU layers whenever it is not the Vulkan build
(`model_params` in `crates/llm/src/model.rs`), so there is no processor mode to measure. There are therefore no
processor numbers for the AI here. This is a finding for the controller, not changed in this task.

**Thinking.** The helper says `thinks = true` for Granite 4.2 3B (as for both Qwen models, and as the catalog does). With
thinking off the prompt ends with the template's empty thinking block. On this input thinking off does change Granite's
reply (not the same text; 34 tokens out with thinking off, 33 with it on), and on costs time: 226 thinking tokens and
5.30 s against 0.82 s with it off, on Metal with a thinking budget of 512. Qwen3.5 4B: 512 thinking tokens (the budget),
14.47 s against 1.29 s, and a different reply too; Qwen3.5 9B: 512 thinking tokens, 24.17 s against 2.33 s.
(With the repeated sentence that was tried first, Granite's two replies were the same text.)

## What is NOT measured

* A Windows processor or graphics card, in any model: the 50x on a Windows processor for Parakeet Ultra is not
  checked, and no Vulkan or DirectML number exists here.
* Parlato 0.14.1's built-in Granite cleanup: its app is not run here, so the bar "not slower than Parlato" for the AI
  cannot be checked. The AI numbers above are the engine's alone.
* Snapdragon and Windows ARM64.
* The AI on the processor on the Mac (the helper has no such mode, see above), and so a Metal against processor
  comparison for the AI.
* Speech on a quiet machine: the programs listed under "The machine" were open, and Parakeet Ultra's default-thread
  median moved by 0.05 s between invocations.
* Real speech: the clip is a text-to-speech voice (one voice, no noise, no pauses to speak of); real recordings may
  decode a little differently. Transcript accuracy was not looked at, only the word count.
* Whisper Base and Whisper Turbo with a language given (`language` "en"), with `Timing::Words`, or with vocabulary or
  `keep_fillers` prompts; the Whisper lines are language auto, `Timing::Segments`.
* Other contexts than 4096 and other prompt lengths for the AI.
