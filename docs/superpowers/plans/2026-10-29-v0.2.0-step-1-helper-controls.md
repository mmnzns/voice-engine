# v0.2.0 step 1: protocol 2 and the AI helper controls, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The local AI helper gets the controls all three apps asked for: an idle policy the app sets (changeable
at any time), load now, unload now, stop a reply without losing the model, thinking on or off, a seed, token
counts, errors as kinds, GGUF inspection, and a guarantee that no user text ever reaches a log. The protocol version
becomes 2.

**Spec revision:** this plan matches spec v2 (2026-10-29, with the app chats' review items). Items from the review
that land in this step: E-A10 (helper lifetime and name), E-A11 (switch and unload models without a restart), E-A12
(no user text in logs), the `gpu_failed` error kind, and `configure` changeable while running.

**Architecture:** `voice-engine-protocol` gains the new requests, events and an `ErrorKind` enum. `voice-engine-llm`
is split into focused files (`inbox.rs` for stdin and cancel, `think.rs` for thinking, `failure.rs` for errors,
`model.rs` for loading, `generate.rs` for complete and embed, `inspect.rs` for GGUF metadata) and implements them.
The helper still runs one request at a time; a `cancel` line is noticed between tokens.

**Tech Stack:** Rust 2024, serde, llama-cpp-2 `=0.1.159` (`json_schema_to_grammar`, `LlamaSampler`,
`gguf::GgufContext`), cargo test.

**Spec:** `docs/superpowers/specs/2026-10-29-voice-engine-v0.2.0-design.md`, section 7. This is plan 1 of 8 (spec
section 12). Plans 2 to 8 are written when the step before them has landed, so they can name real code.

**Ground rules for every task:**

- After every task: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings` and
  `cargo test --workspace` must pass before the commit. The first build compiles llama.cpp and whisper.cpp (several

```rust
//! A failed request: what kind of failure (for the app) and a message (for logs).

use voice_engine_protocol::{ErrorKind, Event};

#[derive(Debug, Clone, PartialEq)]
pub(crate) struct Failure {
    pub error: ErrorKind,
    pub message: String,
}

impl Failure {
    pub fn new(error: ErrorKind, message: impl Into<String>) -> Self {
        Failure {
            error,
            message: message.into(),
        }
    }

    pub fn internal(message: impl Into<String>) -> Self {
        Failure::new(ErrorKind::Internal, message)
    }

    pub fn missing(path: &str) -> Self {
        Failure::new(
            ErrorKind::ModelMissing { path: path.into() },
            format!("couldn't load the AI model: {path} is missing"),
        )
    }

    pub fn out_of_memory(message: impl Into<String>) -> Self {
        Failure::new(ErrorKind::OutOfMemory, message)
    }

    pub fn cancelled() -> Self {
        Failure::new(ErrorKind::Cancelled, "stopped by request")
    }

    pub fn event(self) -> Event {
        Event::Error {
            message: self.message,
            error: self.error,
        }
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    fn a_failure_becomes_an_error_event_with_its_kind() {

            Event::Error {
                message: "couldn't load the AI model: /m.gguf is missing".into(),
                error: ErrorKind::ModelMissing {
                    path: "/m.gguf".into()
                },
            }
        );
        assert_eq!(Failure::cancelled().error, ErrorKind::Cancelled);
        assert_eq!(Failure::internal("x").error, ErrorKind::Internal);
```

```rust
//! Request lines from the app. stdin is read on its own thread; this side waits for the next line (giving up after
//! the idle time, if there is one) and, while a reply is being written, notices a `cancel` without losing any other
//! line that arrived meanwhile.

use std::collections::VecDeque;
use std::sync::mpsc::{Receiver, RecvTimeoutError, TryRecvError};
use std::time::Duration;
use voice_engine_protocol::{Request, decode_request};

pub(crate) enum Next {
    Line(String),
    /// Nothing arrived within the idle time.
    Idle,
    /// The app closed stdin.
    Closed,
}

pub(crate) struct Inbox {
    rx: Receiver<String>,
    queued: VecDeque<String>,
}

impl Inbox {
    pub fn new(rx: Receiver<String>) -> Self {
        Inbox {
            rx,
            queued: VecDeque::new(),
        }
    }

    /// The next line: one that arrived during the last reply first, then a new one, waiting at most `idle` (None:
    /// as long as it takes).
    pub fn next(&mut self, idle: Option<Duration>) -> Next {
        if let Some(line) = self.queued.pop_front() {
            return Next::Line(line);
        }
        match idle {
            None => self.rx.recv().map(Next::Line).unwrap_or(Next::Closed),
            Some(d) => match self.rx.recv_timeout(d) {
                Ok(line) => Next::Line(line),
                Err(RecvTimeoutError::Timeout) => Next::Idle,
                Err(RecvTimeoutError::Disconnected) => Next::Closed,
            },
        }
    }

    /// Called between tokens: true when a `cancel` arrived. Any other line is kept, in order, for after the reply.
    pub fn cancel_requested(&mut self) -> bool {
        loop {
            match self.rx.try_recv() {
                Ok(line) if is_cancel(&line) => return true,
                Ok(line) => self.queued.push_back(line),

            }
        }
    }
```

```rust
//! Thinking: models like Qwen 3.5 can write their reasoning between `<think>` and `</think>` before answering.
//! llama.cpp's built-in template engine can't pass the template's `enable_thinking` switch, so the helper ends the
//! prompt itself: an empty thinking block to answer straight away (what Qwen's own template writes for
//! `enable_thinking=false`), or an opening tag to think first.

pub(crate) const OPEN: &str = "<think>";
pub(crate) const CLOSE: &str = "</think>";

/// The prompt ending that skips thinking.
pub(crate) const SKIP: &str = "<think>\n\n</think>\n\n";
/// The prompt ending that starts thinking.
pub(crate) const START: &str = "<think>\n";
/// Written by the helper when thinking runs past its budget.
pub(crate) const FORCE_END: &str = "\n</think>\n\n";

/// Does a chat template have a thinking step?
pub(crate) fn template_thinks(template: &str) -> bool {
    template.contains(OPEN)
}

/// Where the thinking ends in text written so far (the byte just after `</think>`), if it has.
pub(crate) fn end_of_thinking(text: &[u8]) -> Option<usize> {
    text.windows(CLOSE.len())
        .position(|w| w == CLOSE.as_bytes())
        .map(|i| i + CLOSE.len())
}

/// Removes `<think>...</think>` blocks from an answer. An unclosed block (cut off while thinking) drops everything
/// from the tag on. A closing tag with no opening one drops everything before it. From Ensayo's `ai/json.rs` (MIT).
pub(crate) fn strip_think(text: &str) -> String {
    let mut out = text.to_string();
    if let Some(close) = out.rfind(CLOSE)
        && out.find(OPEN).is_none_or(|open| open > close)
    {
        out = out[close + CLOSE.len()..].to_string();
    }
    while let Some(open) = out.find(OPEN) {
        match out[open..].find(CLOSE) {
            Some(rel) => out.replace_range(open..open + rel + CLOSE.len(), ""),
            None => out.truncate(open),
        }
    }
    out
}
```

```rust
/// Puts one token in the context after the ones already there.
fn feed(
    token: LlamaToken,
    ctx: &mut LlamaContext,
    batch: &mut LlamaBatch,
    n_cur: &mut i32,
) -> Result<(), Failure> {
    batch.clear();
    batch
        .add(token, *n_cur, &[0], true)
        .map_err(|e| Failure::internal(e.to_string()))?;
    *n_cur += 1;
    ctx.decode(batch)
        .map_err(|e| Failure::internal(format!("the AI model failed writing: {e}")))
}

/// The sampling chain for a request. With `answer`, the reply's schema (if any) constrains it; thinking is free
/// text. Temperature 0 is greedy; above 0 the seed makes it repeatable.
fn sampling_chain(
    model: &LlamaModel,
    c: &Completion,
    answer: bool,
) -> Result<LlamaSampler, Failure> {

            Failure::new(
                ErrorKind::BadSchema {
                    detail: e.to_string(),
                },
                format!("bad output schema: {e}"),
            )
        };
        let grammar = llama_cpp_2::json_schema_to_grammar(schema).map_err(|e| bad(&e))?;
        samplers.push(LlamaSampler::grammar(model, &grammar, "root").map_err(|e| bad(&e))?);
    }
    if c.temperature <= 0.0 {
        samplers.push(LlamaSampler::greedy());
    } else {
        samplers.push(LlamaSampler::top_k(40));
        samplers.push(LlamaSampler::top_p(0.9, 1));
        samplers.push(LlamaSampler::temp(c.temperature));
        samplers.push(LlamaSampler::dist(c.seed.unwrap_or(1234)));
    }
    Ok(LlamaSampler::chain_simple(samplers))
}
```

```rust
//! it thinks, how much context it was trained for. Used before offering a file the person imported.

use crate::failure::Failure;
use crate::think;
use llama_cpp_2::gguf::GgufContext;
use std::path::Path;
use voice_engine_protocol::Inspection;

/// gguf_type values (ggml's gguf.h).
const GGUF_TYPE_UINT32: u32 = 4;
const GGUF_TYPE_UINT64: u32 = 10;

pub(crate) fn inspect(path: &str) -> Result<Inspection, Failure> {
    if !Path::new(path).is_file() {
        return Err(Failure::missing(path));
    }
    let gguf = GgufContext::from_file(Path::new(path))
        .ok_or_else(|| Failure::internal(format!("{path} is not a GGUF model file")))?;
    let string = |key: &str| {
        let i = gguf.find_key(key);
        (i >= 0).then(|| gguf.val_str(i)).flatten().map(str::to_string)
    };
    let architecture = string("general.architecture").unwrap_or_default();
    let n_ctx_train = {
        let i = gguf.find_key(&format!("{architecture}.context_length"));
        if i < 0 {
            0
        } else {
            match gguf.kv_type(i) as u32 {
                GGUF_TYPE_UINT32 => gguf.val_u32(i),
                GGUF_TYPE_UINT64 => gguf.val_u64(i).min(u32::MAX as u64) as u32,
                _ => 0,
            }
        }
    };
    let template = string("tokenizer.chat_template");
    Ok(Inspection {
        has_chat_template: template.is_some(),
        thinks: template.as_deref().is_some_and(think::template_thinks),
        n_ctx_train,
        architecture,
    })
}
```

```rust
//! No user text in any log. The helper's only log is stderr; a line that prints a prompt, a reply or a token piece
//! would leak what the person said or wrote. This scans the source so such a line can't be added by accident. Sizes,
//! timings, paths and error kinds are fine.

use std::path::Path;

/// Names that hold user text in the helper's code. A log line that mentions one of them is a leak.
const USER_TEXT: &[&str] = &[

        let path = entry.unwrap().path();
```

```rust
//!   VOICE_ENGINE_TEST_LLM=".../qwen3.5-4b/Qwen3.5-4B-Q4_K_M.gguf" cargo test -p voice-engine-llm --release \
//!     --test real_model -- --ignored --test-threads=1

use std::io::{BufRead, BufReader, Write};
use std::process::{Child, ChildStdin, Command, Stdio};
use voice_engine_protocol::{ErrorKind, Event, decode_event};

struct Helper {
    child: Child,
    /// None once `stderr` has closed it.
    stdin: Option<ChildStdin>,
    out: BufReader<std::process::ChildStdout>,
}

impl Helper {
    fn start() -> Self {
        let mut child = Command::new(env!("CARGO_BIN_EXE_voice-engine-llm"))
            .stdin(Stdio::piped())
            .stdout(Stdio::piped())
            .stderr(Stdio::piped())
            .spawn()
            .unwrap();
        let stdin = child.stdin.take();
        let out = BufReader::new(child.stdout.take().unwrap());
        Helper { child, stdin, out }
    }

    /// Everything the helper wrote to stderr: closes stdin so the helper exits, then reads to the end (call last).
    fn stderr(&mut self) -> String {
        drop(self.stdin.take());
        let mut err = String::new();
        if let Some(mut e) = self.child.stderr.take() {
            use std::io::Read;
            let _ = e.read_to_string(&mut err);
        }
        let _ = self.child.wait();
        err
    }

    fn send(&mut self, request: &serde_json::Value) {
        writeln!(self.stdin.as_mut().expect("stdin still open"), "{request}").unwrap();
    }

    /// The next event that isn't progress.
    fn answer(&mut self) -> Event {
        loop {
            let mut line = String::new();
            self.out.read_line(&mut line).unwrap();
            let ev = decode_event(&line).unwrap_or_else(|e| panic!("{e}: {line}"));
            if !matches!(ev, Event::Progress { .. }) {
                return ev;
            }
        }
    }
}

impl Drop for Helper {
    fn drop(&mut self) {
        let _ = self.child.kill();
    }
}

            .unwrap_or_else(|e| panic!("{}: not JSON ({e}): {}", path.display(), r.text));
        for key in parsed["required"].as_array().into_iter().flatten() {
            assert!(
                reply.get(key.as_str().unwrap()).is_some(),
                "{}: missing {key} in {}",
                path.display(),
                r.text
            );
        }
    }
}
```

```markdown
## Local AI helper protocol

One JSON object per line. Requests (`op`): `ping`, `configure`, `load`, `unload`, `complete`, `cancel`, `embed`,
`inspect`, `devices`. Events (`event`): `ready`, `configured`, `loaded`, `unloaded`, `progress`, `done`, `embedded`,
`inspected`, `devices`, `error`. Match errors on `error.kind`, never on `message`. The current version is
`PROTOCOL_VERSION` in `voice-engine-protocol`; a helper reports it in `ready`.

Lifetime: the helper runs until its stdin closes (the app exited or crashed) or, with an idle time set, until that
long passes without a request. Name the binary as your app wants (Ensayo: the Tauri sidecar `ensayo-llm`); the build
recipe for each target triple is in the release section below (added in step 7). The helper never logs user text:
only sizes, timings, paths and error kinds reach stderr.

Reply schemas: llama.cpp enforces structure (objects, required keys, `additionalProperties: false`, `enum`, `const`,
array sizes). It can't enforce every keyword (a `pattern` using `\d` is accepted as any string), so apps keep
checking replies themselves.
```
