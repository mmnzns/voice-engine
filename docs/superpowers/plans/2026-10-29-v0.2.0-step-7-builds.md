# v0.2.0 Step 7: Builds the Apps Can Ship Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (1) The native libraries (llama.cpp, whisper.cpp) are built with a fixed CPU baseline, never the build machine's instructions: `GGML_NATIVE` off, AVX2 baseline on Windows x64, macOS 11 deployment target on Apple silicon. (2) Windows ARM64 builds and runs the AI helper **and** the speech crate in CI. (3) Any app's CI can build the helpers (`voice-engine-llm` and `voice-engine-stt`) for Windows x64, Windows ARM64 and Mac Apple silicon from a pinned engine tag, named as Tauri sidecars (one file per target triple), with no file copied from the engine repo by hand. (4) Written notes for signing and for the build settings an app must copy when it links the speech crate in process.

**Notion items:** group "5. Builds the apps can ship" (P-A5, P-A6, E-A9, T-A2, E-B6) and spec section 10.

**Facts found by the engine chat (2026-10-29), verify before relying on them:**
- `llama-cpp-sys-2` 0.1.159's `build.rs` sets `GGML_NATIVE` OFF unless `target-cpu=native` is in the Rust flags, and turns `GGML_AVX2`, `GGML_FMA`, `GGML_F16C`, `GGML_BMI2` ON from `CARGO_CFG_TARGET_FEATURE` (see `~/.cargo/registry/src/*/llama-cpp-sys-2-0.1.159/build.rs` around lines 660 to 740). So the AI helper's baseline is set with `-C target-feature=+avx2,+fma,+f16c,+bmi2` for `x86_64-pc-windows-msvc`.
- `whisper-rs-sys` forwards environment variables it recognises to CMake (see its `build.rs` near line 285); whisper.cpp's CMake defaults `GGML_NATIVE` to ON when building natively. Read the `build.rs` of the exact version in `Cargo.lock` to find which variable names are forwarded and set `GGML_NATIVE=OFF` (and the `GGML_AVX2`-family flags) that way.
- Repo CI is `.github/workflows/ci.yml` (jobs `test` on windows-latest and macos-latest, and a manual `windows-gpu` job using `.github/actions/vulkan-sdk`). The repository is public, so the free `windows-11-arm` runner is available.
- A `.cargo/config.toml` in the engine repo does NOT apply when an app depends on the engine as a git dependency (Cargo only reads the config of the workspace being built). So the baseline must also live in the reusable workflow and in the README for apps that link `voice-engine-stt` in process.
